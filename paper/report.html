Reproducibility summary

Scope. Gundam et al. (2025) fine-tuned the 600M-parameter distilled NLLB model with LoRA, separately for each language, to translate named entities better in SemEval-2025 Task 2. I tested the core claim for one language pair, English→Spanish: does LoRA fine-tuning on task data improve translation over the same base model?

Methodology. One Colab notebook on a free T4 GPU. I trained on the benchmark's 739-sentence validation split and evaluated on its 5,338-sentence test split, comparing the base and fine-tuned models under identical data and metrics. The original paper does not report its LoRA settings, so the settings here are my own.

Results. BLEU on the full test set rose from 60.22 to 65.25 (+5.03). A rough entity check on the first 300 test sentences rose from 19.7% to 23.7%, which is about 20% relative against about 8% relative for BLEU. The direction matches the paper's claim. These come from a single training run.

What was easy. The model, the data and a LoRA setup that fits a free GPU were all public. Training took about a minute.

What was difficult. The paper gives no fine-tuning hyperparameters and no Spanish-only entity or COMET scores, so a like-for-like comparison with its numbers was not possible. It also builds training data with the paid Google Translate API, which I replaced with the benchmark's own reference translations.

Communication with original authors. I emailed the senior author on 25 September 2026 with the code.

1 Introduction

Machine translation systems often handle a sentence well and still get its names wrong. Titles of books and films are the clearest case, because their accepted translation is often not a literal one. On the first test sentences of the benchmark used here, the base model translates the title The Signal-Man as "El Hombre de la Señal", while the accepted Spanish title is "El guardavía". It leaves the film About Joan in English, where the reference uses "À propos de Joan".

SemEval-2025 Task 2 (Conia et al., 2025) measures exactly this. The Zero team from IIIT Hyderabad (Gundam et al., 2025) took a small, cheap route: fine-tune NLLB-200-distilled-600M (NLLB Team, 2022) with LoRA (Hu et al., 2022) for each target language. This report checks whether that route helps, for English→Spanish, on a single free GPU.

2 Scope of reproducibility

The claim tested is that LoRA fine-tuning of NLLB-600M on EA-MT data improves translation over the base model, with a larger effect on entity accuracy than on overall translation quality. I do not try to reproduce the paper's absolute scores. It reports Spanish BLEU of 59.14 (Gundam et al., 2025, Table 1) without stating which split was scored, and BLEU values computed with different tools or settings are not comparable (Post, 2018). The trustworthy comparison in this report is between the base and fine-tuned model inside the same experiment.

3 Methodology

Data. The EA-MT benchmark from Hugging Face (sapienzanlp/ea-mt-benchmark, config en-es, CC BY-SA 4.0) has sample, validation and test splits of 72, 739 and 5,338 sentences, each with one to three reference translations and the accepted translations of its entity. The task paper lists the en-es test split as 5,337 sentences; the downloadable file has 5,338 rows with unique ids, and I used all of them. I trained on the validation split and evaluated on the test split, and the two share no ids.

Model and fine-tuning. facebook/nllb-200-distilled-600M with LoRA adapters (rank 16, alpha 32, dropout 0.05) on the attention projections q_proj, k_proj, v_proj and out_proj, using the PEFT library. That trains 4,718,592 of 619,792,384 parameters (0.76%). Training used batch size 8, learning rate 2e-4, 3 epochs and fp16 on one T4 GPU: 279 steps in 62 seconds, ending at a training loss of 0.761. Each training sentence used its first reference translation as the target.

Deviation from the paper. The Zero team translated the task sentences with the Google Translate API and trained on that "silver" data. I trained directly on the benchmark's human reference translations. This removes a paid dependency and changes the training signal, so it is a real difference between the two setups.

Decoding and metrics. Both models decode greedily with the model's default generation settings and at most 128 new tokens. BLEU is corpus-level sacreBLEU (Post, 2018) with default settings, using every reference; sentences with fewer references are padded with their first one. The entity check counts a sentence as correct if any accepted entity translation appears in the output as an exact, case-sensitive substring. The task's official M-ETA metric uses the same idea but ignores letter case (Conia et al., 2025), so my check is slightly stricter. I ran it on the first 300 test sentences only.

Fine-tuning improved BLEU on both the full test set and the 300-sentence sample. Entity accuracy rose by about a fifth in relative terms, more than twice the relative BLEU gain, which is what the paper's argument predicts if the fine-tune mainly teaches the model how names are rendered in Spanish. Absolute entity accuracy stays low for both models. Even after fine-tuning, most test sentences in the sample still miss the accepted entity translation, which fits a method that never looks names up and only learns from 739 examples.

5 Limitations

The result rests on one training run, so it carries no estimate of how much the gain varies with the random seed. The entity figure comes from 300 sentences and a stricter check than the official metric, so its absolute value is rough, though both models were scored the same way. I did not compute COMET, the second official metric, so these numbers cannot be placed on the task leaderboard. Spanish is a high-resource language for NLLB, and the paper covers ten languages; the gain may be larger or smaller elsewhere. Finally, the training data and hyperparameters differ from the original work for the reasons given above.

The repository includes a second notebook, extended_eval.ipynb, that addresses the first three points: three seeds, the official M-ETA and COMET-22 on the full test set, and entity accuracy per entity type. Its results will go into version 2 of this report.
